## Executive summary

Northlight RealCapture is now a credible production-grade demo for the core RealCapture story:

- one property record;
- role-aware workflow;
- photographer-owned availability/calendar;
- Dropbox-backed secure media;
- revision loop;
- approved immutable delivery release;
- Admin/Owner/Agent/Photographer/Editor access checks;
- connected Google Workspace and Dropbox health;
- calm, premium, mostly clear UI across desktop/tablet/mobile.

During UAT, four material blockers were found and fixed:

1. Admin bootstrap failed against production integration schema drift.
2. Review publication failed when older edited Dropbox files remained in the source folder.
3. Approved release temporary file links failed for all roles.
4. Admin deactivate/reactivate returned 500 after actually changing account state.

All four fixes were committed, pushed and production-verified.

## Architecture/integration assessment

The current integration architecture is directionally correct.

### Dropbox

Dropbox webhooks are only a wake-up signal; they do not include the actual file changes. The durable design should keep a cursor and call `files/list_folder/continue` to reconcile truth. Northlight is already aligned with this pattern through cursor/state/retry tests and Dropbox sync logic.

Sources:

- https://www.dropbox.com/developers/reference/webhooks
- https://developers.dropbox.com/detecting-changes-guide

### Google Calendar

Google Calendar also needs both notification channels and incremental sync tokens. Push notifications improve timeliness, but missed/out-of-order events must be recovered by sync-token based reconciliation. Northlight’s watch/channel/cursor tests match this pattern.

Sources:

- https://developers.google.com/workspace/calendar/api/guides/push
- https://developers.google.com/workspace/calendar/api/guides/sync

### Xero

Xero should be treated as deferred but architecturally similar: signed webhook intake, idempotent event handling, follow-up API fetch, retry-safe invoice creation/update, and reconciliation after ambiguous provider failures.

Source:

- https://developer.xero.com/documentation/guides/webhooks/overview/
